## Why this change

The custom binary banner trusted an unversioned `ktahv-consent` value indefinitely and could not express analytics-only or advertising-only choices. The shared head restore accepted the historical fleet record before validating its age. AHV now uses locally served CookieConsent 3.1.0, upstream commit `e6279509aab5b96be198297b0283b321ad76b0a9`, verified as GitHub's latest release on 7 October 2026. Its MIT license, untouched distribution files and SHA-256 manifest are in `public/consent/vendor`. No shared package or dependency lock is changed.

The head starts denied. Only CookieConsent's validated current revision can start optional SDKs. Analytics gates GA4 and Clarity (including session replay); advertising gates Google Ads and Meta. Reject and accept are equally prominent; the settings panel offers separate optional categories. Every page retains a translated preferences entry point. Saved changes revoke consent before reloading to unload SDK timers/listeners. Cross-tab changes reload. Expired, malformed or old-revision grants stop; recent refusals suppress automatic requests to opt back in. Storage failure honors the current page choice and re-prompts next visit. Failure to load the module leaves optional SDKs blocked and offers retry.

Old explicit rejection migrates once. Old blanket acceptance re-prompts instead of silently authorizing new categories. The old key remains only for captured-view presentation compatibility. GPC keeps advertising off, including when a previously accepted record exists. Geography changes only prompt presentation, as described below. Optional vendors still require explicit, validated permission in every country.

Existing public measurement IDs, build-time analytics switch, safe URL guards, customer-data suppression, successful-enquiry requirement, lead deduplication and staging conversion safeguards are preserved. No synthetic conversions or real visitor data were transmitted during QA. Account-side Google Ads/Meta receipt reconciliation remains a separate checkpoint.

## Regional presentation and refusal retention

This is a presentation policy, not a legal applicability map. EEA countries plus the UK and Switzerland receive an automatic prompt. Recognized other countries, including India, the US, Canada and Brazil, receive the permanent translated settings control with all optional categories off. Unknown country, missing evidence, timeout, malformed response or geo failure receives the automatic prompt. No non-European jurisdiction is treated as unrestricted, and no retargeting, cookieless analytics or replay is enabled by geography. Avoiding an interruption does not recover unconsented retargeting.

On the exact HTTPS apex and www hostnames, the browser reads the already-existing first-party Cloudflare `/cdn-cgi/trace` endpoint. It omits credentials and referrer, disallows redirects, requests no caching, limits the body to 4 KiB and applies a 1.5-second timeout including body reading. Only a single matching host, a single recognized country and a single timestamp within 60 seconds (maximum ten seconds ahead for clock skew) can reduce the prompt. Positive or malformed Age, HIT/STALE/other unexpected cache status, redirects, stale timestamps and duplicate fields fail strict. The adapter discards the body and never exports, logs or stores IP, country, user agent or the trace response.

Cloudflare [documents ownership and diagnostic use of this endpoint](https://developers.cloudflare.com/fundamentals/reference/cdn-cgi-endpoint/); it does not promise a stable jurisdiction API. Current public read-only evidence finds fresh replies and client country-header spoofing ignored, but no explicit response Cache-Control. These checks reduce reuse risk; they cannot prove a country's legal applicability or a worldwide multi-location cache guarantee. Any protocol change falls back to the automatic prompt. This limitation affects presentation only, never vendor permission.

Other hosts use the first-party `/api/consent-region/` endpoint. It trusts Vercel's country signal only with the current exact Vercel deployment hostname and expected platform headers, and rejects proxy indicators. Custom or ambiguous origins always return automatic. The response contains only a version and presentation enum, is dynamic and sends no-store headers for the browser and both CDN layers. Static page HTML and its cache do not vary by visitor country. No new geolocation provider, permission, credential or remote configuration was introduced.

Valid existing explicit choices remain valid regardless of geography. Grants expire after 182 days. Full refusals last 366 days; a separate necessary, identifier-free refusal record preserves each denied category for 366 days across grant expiry or policy revision. Ordinary visits do not extend refusal timestamps. While a recent refusal exists, automatic re-prompting is suppressed and any expired grant stays off; the visitor can voluntarily reopen settings and choose again. GPC additionally suppresses advertising and automatic prompting, and its refusal remains after the signal is removed. This intentionally exceeds the CPPA's [at-least-twelve-month waiting period before asking to opt back into sale/sharing](https://cppa.ca.gov/announcements/2025/20250909.html), including leap years, without claiming the site's sale/sharing classification has been legally settled. Clearing browser storage necessarily removes locally remembered choices.

The 13 locales and campaign layouts use the same bridge. Existing translations say vendors are off until chosen and remain accurate in both presentation modes. No policy copy or medical content was silently rewritten. Clarity remains off before analytics permission: its [cookie-less capability](https://learn.microsoft.com/en-us/clarity/setup-and-installation/consent-mode) is not itself a legal basis. The CNIL's [February 2026 session replay consultation](https://www.cnil.fr/en/session-replay-cnil-launches-public-consultation-its-draft-recommendation) is a draft, not a final rule. Functional first-party enquiry persistence and operational receipt counts remain separate from ad conversion tracking; this candidate neither adds a counter nor changes lead routing.

The configured Ads alias still fans out to the separately identified destinations in the existing authenticated evidence. This candidate does not alter IDs, Google routing or remote account settings. No test telemetry or conversion is sent; optional SDK tests intercept every collection request. Do not publish this consent candidate as though the destination mismatch were resolved, and do not block unrelated authorized website changes on that account dependency.
