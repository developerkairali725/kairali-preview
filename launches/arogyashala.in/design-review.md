## Detailed findings

1. **The consent banner erases the second door on every first mobile visit (the page's one job, compromised).**
   Measured at 375×812 first paint: banner `[data-consent-banner]` is fixed at bottom, 163.3px tall, top y=648.8; the customers' door occupies y 648.6→822.2 — overlap 163.3px, i.e. **everything of it that the viewport shows**. critic-mobile-firstpaint-consent.png: a first-time visitor — including the walk-in customer this door exists for, on the phone she saw the board with — sees a one-door page. The banner is compliant and its buttons are 44px, but the site makes no accommodation: packages/consent sets `data-consent-open` on `<html>` precisely so pages can yield, and globals.css never references it. After a choice the hinge is perfect (critic-mobile-firstview-after-consent.png) — but a landing page only gets one first paint.
2. **Keyboard focus is invisible on the doors — a hard ch.07/10 violation.**
   brand-tokens.css `:where(a,…):focus-visible { outline:none; box-shadow: var(--focus-ring) }` (specificity 0,1,0) loses the box-shadow to `.door { box-shadow: var(--shadow-warm) }` (also 0,1,0, but globals.css loads after brand-tokens.css) while its `outline:none` still applies → a keyboard user tabbing to either door gets **no indicator whatsoever**. Verified with real Tab keypresses: `matchesFocusVisible: true`, computed `boxShadow: rgba(94,66,22,…) …` (shadow-warm only), `outlineStyle: none`; critic-focus-door.png shows two identical doors, one of them focused. The builder's qa-desktop-door-focus.png shows a ring this CSS cannot render — re-evidence after the fix. Same class of gap: `summary` is absent from the token focus selector, so FAQ rows fall back to the UA outline.
3. **The annotated figure's callouts typeset themselves — badly.**
   `.callouts li { display:flex; gap:12px }` turns each list item into marker | `<strong>` | anonymous-text flex columns, so every label becomes its own narrow wrapping column mid-sentence: at 375 the labels render "The / Kairali / shelf" and "The / authorised- / counter mark" (a hyphen-split across three lines) with the description in a separate ragged column (critic-storefront-mobile.png; desktop version critic-storefront-desktop.png has the same fault at smaller amplitude). The device the research called the replacement for the locations list we cannot ship deserves deliberate typography, not accidental columns. Also inside the SVG: the board lettering is `fontFamily="Georgia, serif"` — the page's most brand-charged pixels are set in the fallback face, not Kurale.
4. **The page's structured data contradicts its own trust band.**
   Rendered JSON-LD (verified via curl): `"@type":"Organization","name":"Kairali Ayurvedic Group","foundingDate":"1908"` — while the visible trust band says "Kairali Ayurvedic Group, founded 1989" and the 16 Jul PR #65 ruling locks 1908 to *family lineage only*. Source: `kairaliOrganization()` in packages/schema/src/index.js:71 prefills `foundingDate: "1908"` — a library-level defect that predates the ruling and ships on every site using the helper, but on THIS page it sits ~2,000px from copy asserting the opposite. Machines read both.
5. **"— computed, not claimed." is internal doctrine leaking into customer copy.**
   Trust band, first dd: "118 years of unbroken lineage — computed, not claimed." The facts law is our discipline, not the chemist's vocabulary; to a first-time visitor it reads as an odd hedge. Say the fact like a human ("118 unbroken years, father to son") or let "since 1908" carry it.
6. **Desktop composition goes single-lung below the storefront row.**
   At 1280, everything after the figure — flow heading, 01–03, CTA row, verify section, FAQ — occupies the left 720px with empty ivory to the right (critic-desktop-full.png). Generous air is the stated register, and the storefront row proves the page knows how to use the width; one more counterweight (FAQ at two columns ≥1024px, or the flow numerals gutter-hung) would finish the desktop read. Composition polish, not a gate item.

## Fix list (for the builder — gate re-run required after)

1. **Consent/door collision (finding 1):** make the first mobile paint show both door titles. Cheapest honest combination: tighten `.hero-dark` padding and door padding below ~480px AND compact the banner's mobile footprint, or use the provided hook — e.g. `html[data-consent-open] …` to shorten the hero while the banner is open. Acceptance test: at 375×812 with no stored consent, both `.door-title` elements fully visible above the banner top.
2. **Focus ring (finding 2):** in globals.css add `.door:focus-visible { box-shadow: var(--shadow-warm), var(--focus-ring); }` and `.faq-list summary:focus-visible { outline: none; box-shadow: var(--focus-ring); }`. Acceptance: Tab order shows the leaf ring on doors and summaries; re-shoot critic-focus-door.png equivalent.
3. **Callout typesetting (finding 3):** `.callouts li { display:grid; grid-template-columns: 24px 1fr; }` (marker | one flowing paragraph with `<strong>` inline) — no mid-sentence columns, no hyphen-split labels at any viewport. While in the figure: board `<text>` → `fontFamily="var(--font-display)"`.
4. **JSON-LD founding fact (finding 4):** fix `kairaliOrganization()` in packages/schema — `foundingDate: "1989"` per PR #65; keep 1908 as lineage phrasing in prose fields only. Library-level: flag to Abilash, ripples to every fleet site; do not ship this page's preview with self-contradicting structured data.
5. **Copy (finding 5):** replace "— computed, not claimed." with human phrasing.
6. **FAQ chrome:** style the disclosure marker (custom `::marker`/chevron in forest-500, inside the content box so it never sits in the mobile gutter) so the fifth device reads designed, not default.

## Final verdict — iteration 1

**8.4 / 10 — FAIL against the ≥9.0 gate. Does not go to C-1 in this state.**
The concept work is the best in the fleet: all five differentiation devices exist, the dark-hero-plus-doors hinge is genuinely memorable, the copy is honest to the bone, and the page is feather-light for exactly the phone that matters. What fails is finishing: a cookie banner sitting on the signature device at first paint, an invisible focus ring on that same device, and accidental typography inside the annotated figure. Every fix above is CSS-or-one-line cheap except the schema fact (a deliberate library PR). A focused pass should clear 9.0 on iteration 2 of 3 — the scorecard goes to the builder unsoftened.
