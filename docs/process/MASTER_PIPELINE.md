## What we do today, and why it produces average work

We **build first and audit after**. Every AEO, SEO, design and compliance check we run happens *after* the pages exist — so it can only report damage. The decisions that actually determine whether a site wins (who it's for, what words they use, what pages exist, what each page claims) are made informally, mid-build, by an agent in a hurry. **That is how we shipped a demand map that understated turmeric 11×, and how we shipped a physician's name on 3,400 reviews that never happened.**

## What changes

Work moves into **14 labelled stages, executed one at a time**. The agent must announce which stage it is entering. **A stage cannot be entered until the previous stage's evidence exists as a committed file** — and from now on, that evidence must be **produced by the checking program itself**, not typed by the agent. That last sentence is the single most important change in this document.

## 0.2 ★ THE VERDICT CONTRACT — the fix that makes every other gate real

> **Adversarial finding (order-and-evidence F3, F8):** the draft bound every verdict to the SHA-256 of the artifact it judged — but **a hash is computable by anyone holding the artifact.** Nothing bound a verdict to an *execution*. Forging a clean matrix walk required writing one JSON file. **The mechanism assigned to catch "declared binding in a .md file" was defeated by exactly that failure.**

**A verdict is valid only if it was emitted by the enforcing command itself.** Schema, mandatory, every field:

```json
{
  "gate": "G3-PRE",
  "status": "PASS|FAIL",
  "artifact_path": "docs/.../keyword-map.json",
  "artifact_sha256": "…",
  "rubric_sha256": "…",
  "command": "node scripts/keyword-validate.mjs",
  "argv": ["--artifact", "…"],
  "exit_code": 0,
  "started_at": "2026-07-15T19:30:47+05:30",
  "finished_at": "2026-07-15T19:30:49+05:30",
  "runner": "github-actions|local",
  "ci_run_url": "https://github.com/…/runs/…",
  "control_probe": { "name": "…", "expected": true, "observed": true }
}
```

**`scripts/matrix-walk.mjs` REJECTS a verdict that:** lacks any field · has `exit_code != 0` with `status: PASS` · whose `artifact_sha256` no longer matches the file on disk · whose **git-blame author is a human or agent edit rather than a CI job** · whose `control_probe.observed != expected` (§0.6).

**Without this, §12 item #4 does not answer Abilash's #1 ask.** With it, the walk is a proof rather than a ritual.

## 0.3 ★ THE RE-ENTRY CONTRACT — `SΔ`, the change lane

> **Adversarial finding (tracks F1, completeness F8, practicality F8c):** the draft modelled every site as one greenfield walk to launch. **whatisayurveda is already live**; ~3,380 of its pages arrive *after* S10. Under the draft, publishing monograph #5 required a 9-stage walk no domain has ever run — and appending a row to the keyword map changed its hash, voiding every downstream gate. **S5 required the map to be revised; S9 voided everything when it was. Both rules could not be satisfied.**

**Hash binding is per-SLICE, not per-file.** An artifact is hashed by row-set (`keyword-url-map.tsv` → per-row hash + a manifest hash). Appending rows voids **only the rows appended** and the gates that consumed them.

**Change class → re-entry stage:**

| Change | Re-enters at | Gates re-walked |
|---|---|---|
| Copy edit, no new claim | **S6** | `G6-PRE`, `G6-CITE`, `G8` |
| New or changed **claim** | **S6** | `G6-*` incl. `G6-FACT`, `G6-HUMAN-A` if badged |
| New **page / URL** | **S5** | `G5-*` (slice), then S6→S9 for the slice |
| New **cluster** | **S3** | `G3-*` (slice) → S4 delta → S5 slice |
| **Template** change | **S7** | `G7-*`, then S8/S9 full |
| Wave-N content batch | **S5** (slice) | `G5-PRE` slice → `G6` → `G8` → `G9-Δ` |
| Shopify PDP copy | **S6** | `G6-*` + **B4 post-execution diff** |
| LP variant under an approved campaign mandate | **S6** | `G6-*` + `G7-PRE`. **No new Director gate** |

**THE RE-ENTRY RULE.** Changing an artifact voids its verdict and every downstream verdict that consumed it. Re-running voided `PRE`/`CITE` gates is **mandatory and free**. Re-running voided `FACT`/`PROC` gates is mandatory unless a **committed waiver names the reason and the human**. `matrix-walk.mjs` prints the void chain. **A voided gate is a normal event. An *unrepaired* voided gate is the failure.**

> Without this rule the honest response to finding a mistake late is *"don't touch the artifact"* — which is how S5 mistakes get built instead of corrected.

## 1.5 The structural finding, stated once

> **The deepest flaw in our process is not a missing step. It is that auditing happens after building.** An audit that runs after the sitemap ships can only report damage; the same check at S5 prevents it.

Every one of the seven compliance tributaries is cheapest at **S1** (a decision) or **S5–S6** (an architecture/claim), and most expensive at **S10–S11** (a live artifact). **Not one is cheapest at S9. S9 is where we currently run all of them.** Accessibility: **~1× at S7 vs ~30× at S10** **[DQ]** — *a vendor blog restating the classic defect-cost curve. It is indicative, not proof. The draft called it "proves this arithmetically" and hung this section on it; that word is withdrawn* (order-and-evidence S4).

## 1.6 The cost asymmetry that justifies the whole order

From Google's own docs **[S]**:
- Changing a keyword→URL decision **before** the sitemap ships: **cost ≈ editing a spreadsheet cell.**
- Changing it **after**: **cost = a site migration** — redirect mapping, equity loss, re-crawl, and *"keep the redirects for as long as possible, generally at least 1 year"* of maintenance debt.

**The sitemap is the point where cheap decisions become expensive ones.** That asymmetry is the entire justification for his ordering, and it is why *"we'll fix the URLs later"* is never a real plan.

### ★★ K7 — V1–V10, and the type model that is the actual fix

**V1's four-state type model, adopted VERBATIM from `research-keyword-rigor.md` §6. It is not paraphrased again, because paraphrasing it is what broke it:**

```
{volume: <int>, status: "measured"}
{volume: null,  status: "no_data"}        ← endpoint returned a row, no number
```

## `S9` · STAGE IT AND PROVE IT — ★ THE FINAL PRE-LAUNCH MATRIX WALK ★

> **Abilash:** *"Before declaring any site ready to ship: **re-walk the ENTIRE matrix and prove every step with machine evidence.**"*
> *"I don't want to burn millions of tokens to find out we did very average work because you hallucinated, forgot to run some rule, or missed a step."*

**(a) Purpose.** Prove, mechanically, that every stage **actually ran** — that its artifact **has not changed since it passed** — and that **the built site IS the artifact.**

**(c) Inputs.** Every `audits/<domain>/G*-verdict.json` from S0→S8.

**(d) The work — the walk itself.**

1. **For every stage S0→S8: its exit artifact exists, is committed, and its gate emitted a PASS.**
2. **★ THE VERDICT CONTRACT (§0.2) — the idea that makes the walk real.** Every verdict carries `{command, argv, exit_code, started_at, finished_at, runner, ci_run_url, artifact_sha256, control_probe}` and **was emitted by the enforcing command itself**.
   - **Hash mismatch ⇒ the artifact changed after it passed ⇒ that gate is VOID.**
   - **`exit_code != 0` with `status: PASS` ⇒ FAIL.**
   - **git-blame author is a human/agent edit rather than a CI job ⇒ FAIL.**
   - **A voided gate is repaired per the `SΔ` RE-ENTRY RULE (§0.3), not routed around.**

Forging a clean matrix walk required writing one JSON file — which is **epistemically identical to a .md file asserting a rule binds. ## 11.2 The four-layer model — stops at the first failure

```
L0  MACHINE PRECONDITION   deterministic, free, un-arguable
    ├─ artifact exists? committed? non-empty?
    ├─ required columns/fields present? types correct?
    ├─ set/graph invariants (locale parity, 1:1 URL binding, single-hop 301, zero orphans)
    ├─ CITATION RESOLUTION: every URL → HTTP 200 + quoted string present on page
    └─ CONTROL PROBE: a known-present control returns non-zero    ← §0.6
    ↓ FAIL here = exit 2, ZERO tokens spent.   ← where the DataForSEO failure dies

L1  FACT GROUNDING (Perplexity)   "is this claim TRUE?"
    └─ raw artifact only; its own citations re-resolved at L0 rules

L2  PROCESS + QUALITY (GPT-5)   "is this GOOD, and did we skip a step?"
    └─ never told what L0/L1 concluded (bandwagon bias)

L3  HUMAN   accountable sign-off. Cannot be delegated to L0–L2.
```

> **The rule that makes this work: a higher layer may NEVER overturn a lower one.** Perplexity cannot argue a broken citation into existence; GPT-5 cannot decide a 404 is fine. **Layers only ADD findings.**

## 11.3 Anti-rubber-stamp design — for MODELS and for HUMANS

| Rule | Applies to | Why |
|---|---|---|
| **Different model family from the generator** | models | *"A different model family is not invested in the work being right."* Already true — keep it |
| **An auditor never sees a prior verdict** | models | Bandwagon bias is measured and real |
| **Default-to-FAIL, enforced by the HARNESS, not the prompt** | models | A prompt can be talked out of a verdict; **an exit code cannot** — and §0.2 is what finally captures the exit code |
| **Citations resolved by MACHINE, never judged by model** | models | *"Confidently wrong with a real-looking citation"* |
| **Rubrics ship with a worked golden example** | models | ★ **The highest-leverage finding in the auditor research:** **reference-guided grading cut a judge's failure rate several-fold — nearly free, and larger than any model upgrade we could buy** **[P:sib]**. ⚠️ *The draft cited MT-Bench's 70/30/15% as "GPT-4's grading failure rate" flat; the figures are, to the order-critic's recollection, **scoped to math/reasoning questions specifically**. **A real number doing work outside the scope it was measured in.** The mechanism is adopted; the percentages are withdrawn pending a fact-grounding pass* |
| **Length must not buy a pass** | models | Verbosity bias |
| **⚠️ Judges are LENIENT when uncertain** | models | The finding that most changes the design — **which is exactly why L0 must carry the weight** |
| **⚠️ A judge shown our doctrine will defer to it** | models | **Hence: Perplexity is never passed the pipeline doctrine at all** |
| **★ 3 sittings per site, capped** | **humans** | A gate needing an afternoon is a signature |
| **★ One page, recommendation stated at the top, including "I recommend KILL"** | **humans** | A gate he can clear in 10 min with real information is a real gate |
| **★ Unverified items listed AS unverified in the pack he reads** | **humans** | An "all green" pack is a rubber stamp with extra steps |
| **★ The agent never decides** | **humans** | The recommendation is not the decision |

**The regression corpus — the acid test.** **The DataForSEO demand map, unmodified, must FAIL `G3-PRE`.** ⚠️ **AND IT NEEDS A SECOND FIXTURE, because the first one passes for the wrong reason:** the real map fails on **assertion #1** (it is full of compound seeds), **so the suite goes green while the zero-challenge hole is never tested.** *A regression corpus that passes for the wrong reason is worse than none.* **Fixture 2: a demand map with clean seeds and one implausible ontology-class zero. If `G3-PRE` passes it, the gate does not do what §0.7 says it does.** **Fixture 3: a lint whose regex is deliberately broken — the control probe must catch it.**

## 11.4 Changing a rubric or a threshold

**A failing gate is NEVER fixed by weakening it** (KD-g). Rubrics will live at `docs/process/rubrics/<gate-id>.md` (**build #5 — they do not exist today, §0.5**), are **hashed into every verdict**, and changing one requires: a named reason, a DECISIONS entry, and Abilash's approval. **A rubric diff inside a PR that also makes the gate pass is, by default, a finding.**

## 11.5 The fix-and-rerun loop is STATELESS

**Never argue with an auditor.** Fix the artifact; re-run from scratch; the auditor sees no history. **2–3 passes.** The agent judges the critique, implements, re-runs — but **never negotiates a verdict.**

## 11.6 ★ Trigger scope — the auditors are PATH-SCOPED

> *Nothing in the draft said **when** the auditors run. Wired into CI naively, every PR — a README typo, a dependency bump, a `soul.md` comma — pays for GPT-5 **and** Perplexity. §11.1's defence is about **which checks**, not **which diffs**. Against an explicit "don't burn millions of tokens" brief, that is the whole hazard.*

**`FACT` and `PROC` auditors fire ONLY on:** `docs/*-inputs/**` · `**/keyword-map.json` · `**/*-keyword-url-map.tsv` · `**/content/**` · `launches/**/business-case.md`.
**They NEVER fire on code-only diffs.** One `paths:` block in the workflow.

## 11.7 ★ `G-FLEET` — the fleet invariant no per-domain gate can express

> *Every artifact in this pipeline is `docs/<entity>-inputs/<domain>-*`; every verdict is `audits/<domain>/`; every gate ID is per-domain. **But the fleet has cross-domain 301 dependencies** — kairali.com's protection map points **12 URLs at the live Shopify store (Track B), 6 at kairalicenters (mid-rebuild), 3 at whatisayurveda**.*
>
> **The failure no per-domain gate can catch, using only this pipeline's own rules:**
> 1. kairali.com passes `G5` — its 12 `/products/*` targets resolve 200. Verdict + hash committed.
> 2. Later, the store runs **B4.5**: *"a discontinued no-traffic SKU is a **410**, not a 301."* **"No-traffic" is judged on the STORE's analytics — blind to 12 legacy kairali.com URLs pointed at it.**
> 3. The 410 lands. kairali.com's `G5` verdict is now false — **but its artifact hash still matches**, so `G9-PRE` passes and S9 certifies the site.
> 4. **~12 backlinked legacy URLs now 301 into a 410** — which is `G0`'s own DON'T, **committed by a different site's gate passing correctly.**
>
> **This is worse than a stale check: the hash binding ACTIVELY CERTIFIES the stale verdict**, because the hash proves *our* file didn't change, and our file was never the thing that changed. **The hash binding proves internal consistency and is silent about external dependencies — and on a 28-site fleet with sibling 301s, the external dependencies are where the equity is.**

**RULING: cross-domain 301 targets are a FLEET INVARIANT.**
- **`docs/redirects/inbound-register.tsv`** — for every URL: who points at it, from which domain, on which track. **Appended at S0, consulted at S5 and at B4.5.**
- **`G11-FLEET`** — a **scheduled monthly** cross-domain target-resolve check. *Targets you don't own need re-verification, not a snapshot.*
- **A "no-traffic SKU" that is the single-hop target of 12 backlinked legacy URLs is not a no-traffic SKU.**
