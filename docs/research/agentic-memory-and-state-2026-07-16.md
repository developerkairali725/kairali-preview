## Executive summary

Practitioners and researchers converge on the same architecture Kairali already has — an external, git-versioned compiled-memory layer (Karpathy's LLM Wiki pattern) is mandatory because models have no continual learning and only context-window "working memory" — but they also converge on the two mechanisms Kairali is missing: (1) derived state provably rots even in purpose-built systems ("incomplete forgetting," "temporal memory contamination," mcp_agent_mail's own "mailbox state can drift" admission), so a scheduled reconcile pass against external ground truth (GitHub API PR states, inbound email via a Service-Desk-style email-to-issue bridge) is required, not just careful writes; and (2) session resume must load a small machine-readable boot file whose status fields are flipped rather than prose-edited (Anthropic's JSON feature-list finding), since compaction and free-form notes measurably fail across context windows. The meta-anxiety about harness-building is partly misplaced — production-grade agent harnesses are ~98% deterministic plumbing — but that plumbing should be cheap deterministic scripts, not token-burning agent sessions, and new memory frameworks (Mem0-style probabilistic stores) should NOT be added: they trade quality for cost and add a measured safety-degradation vector as memory grows. Tomorrow-morning plan: KEEP the wiki/CLAUDE.md/append-only-git layer (it matches or exceeds published best practice — stop rebuilding it); ADD a snapshot-generated JSON boot contract, a cron reconcile job folding GitHub+email truth into repo state, and a same-session directive-capture rule with source/timestamp provenance; CUT further memory-framework construction and broad-retention log retrieval in favor of compact recency-biased state.

### 6. [HIGH] 'Incomplete forgetting' is a documented general mechanism: correcting or deleting a memory in its source location does not fix agent state because derived copies survive in compressed summaries, retrieval indices, reflected lessons, and propagated stores. Kairali's merged-PR-still-BLOCKED incident belongs to this same derived-state-consistency failure class (mechanistically a missed external-event write rather than deletion residue — the verifier required this softening). ADOPTION: the fix is cascade re-derivation of ALL derived views (wiki, snapshot, morning brief) from ground truth on a schedule, not more careful individual writes.

- **Evidence:** Verbatim from §3.5 (pypdf extraction): 'Deleting only the visible entry can therefore leave retrievable residues in compressed summaries, retrieval indices, or propagated copies, allowing contamination to reappear after apparent cleanup'; 'a single memory item may leave derivatives across raw dialogue logs, summarized memory cards, vector indexes, reflected lessons, shared stores, and audit records.' Independently corroborated by Always-On Agents survey (arXiv 2606.30306: deletion/correction leaves stale derived artifacts because systems lack provenance links across representations), Agentic Unlearning (2602.17692), MEMOREPAIR (2605.07242), OWASP 2026 ASI06.

### 7. [MEDIUM] Memory bloat is a measured safety problem, not just a cost problem: memory-equipped agents show systematically rising safety-violation rates as benign memory accumulates ('temporal memory contamination'), and one of the three identified mechanisms is 'stale information' — outdated memory content overriding later corrections — the exact general form of Kairali's stale-log failures. Independently, the STALE benchmark shows the best model detects invalidated memories only 55.2% of the time. ADOPTION: staleness must be solved structurally (reconcile against ground truth), not by asking the model to notice; and the finding that recency-biased short-term memory architectures stay flat (0.1–0.2 violation rate) while broad-retrieval/long-retention ones climb to 0.3–0.5 favors compact fresh snapshots over broad retrieval of accumulated logs.

- **Evidence:** Verbatim from abstract: 'Memory-induced violation rates show a robust upward trend with exposure length on both agent classes... We call this failure mode temporal memory contamination.' §3.4 verbatim: 'cross-context leakage..., stale information (outdated content overrides corrections), and summarization combination.' Inputs human-verified non-adversarial. Verifier qualifications: single non-peer-reviewed v1 preprint for the headline trend; architecture-dependent, not universal; LLM-judge precision 0.50–0.69 so rates are upper bounds. Staleness mechanism multiply corroborated (STALE, MemConflict, freshness-tracking papers, all May–June 2026).

### 8. [MEDIUM] Mem0 quantifies the session-resume trade-off but is NOT a model to adopt: its staleness resolution is an LLM judgment call (ADD/UPDATE/DELETE/NOOP against top-s similar memories — probabilistic, documented to mis-resolve), and on LOCOMO full-context re-derivation beats it on quality (72.90% vs 66.88% LLM-judge) while Mem0 cuts p95 latency ~91% (1.44s vs 17.1s) and >90% of tokens (~1,764 vs ~26,031). ADOPTION: full re-derivation is the quality ceiling, compiled memory the cost floor — Kairali's deterministic snapshot-plus-wiki approach captures the cost savings WITHOUT delegating truth-resolution to a probabilistic model, so do not bolt on Mem0/Letta-style stores.

- **Evidence:** Primary paper (Mem0-authored) confirms the four-op LLM consolidation loop verbatim and Tables 1–2 numbers exactly. Follow-up papers (SAGE arXiv 2605.30711, Memory-R1 arXiv 2508.19828) document per-write cost and mis-resolution in the vanilla operation chooser.

## Claims REFUTED by verification (do not act on these)

- **Karpathy identifies staleness/drift as the primary failure mode of the compiled-wiki memory pattern — pages silently go stale when cross-references are under-updated during ingest — and prescribes a periodic, non-optional 'lint' pass that checks for contradictions, stale claims, orphan pages, and missing cross-references.** — 
- **Karpathy publicly introduced his 'LLM OS' framing in a post on X dated November 11, 2023, explicitly presenting it as an in-progress concept rather than a finished system.** — 
- **Anthropic's minimal sufficient state layer for weeks-long agent work is deliberately small — a dedicated first 'initializer' session creates an init.sh script, a single progress-log file, and git commits; every subsequent session boots by reading git logs plus the progress file (an explicit session boot contract), not by re-deriving context.** — 

## Caveats

Time-sensitivity: the Anthropic harness findings are indexed to the Opus 4.5 era (Nov 2025) and Anthropic's own Mar-2026 follow-up shows the required harness thins with each model generation — the boot-contract design should be revisited as models improve. Single-source risks: the temporal-memory-contamination magnitude rests on one non-peer-reviewed v1 preprint (arXiv 2605.17830) with an LLM judge of 0.50–0.69 precision (rates are upper bounds) and architecture-dependent results; the 1.6%/98.4% Claude Code split is a community estimate cited by a paper, not a first-party measurement. Vendor bias: all Mem0 latency/token numbers are vendor-authored, disputed by Zep, and measured on a conversational benchmark (LOCOMO) that does not transfer cleanly to multi-week code projects — treat as directional. Two adjacent claims were REFUTED in verification and must not appear in downstream docs as sourced: Karpathy does NOT prescribe a mandatory wiki lint pass (that is Kairali's own extension), and Anthropic's article does NOT describe the specific 'init.sh + single progress file' minimal boot contract. Coverage gaps: research questions 5 (cross-model adversarial verification value) and 6 (mid-2026 model-per-task fitness) produced zero confirmed claims, so this report deliberately makes no recommendation on multi-model judging panels or model selection — those need a separate research pass rather than unsourced guesses. The Kairali BLOCKED-PR incident analogy to 'incomplete forgetting' was verifier-softened: mechanistically it was a missed external-event write, not deletion residue; both belong to the derived-state-consistency failure class, which is what the reconcile recommendation targets.
